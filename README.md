# Zinor — متجر جزائري + واتساب بالذكاء الاصطناعي + شركات التوصيل

مسار الخدمة (مأخوذ من الفيديو المرجعي): **الكوموند تدخل** (من متجر مربوط، من محادثة واتساب، أو يسجّلها الموظف) ← **تتأكد في واتساب** (موافقة في المحادثة أو أزرار) ← **تروح أوتوماتيكياً لشركة التوصيل** بلا مكالمة ← **الزبون يتبّع** ويوصلو **تذكير كي الطرد يخرج مع الليفرور** ← **التسليم أو الروتور** ← **لوحة وحدة** فيها كل شي مع الـretour حسب الولاية.

## التشغيل

يلزم **Node.js 22.13 أو أحدث** (قاعدة البيانات SQLite مدمجة في Node، ما تحتاج حتى خادم آخر).

```bash
cp .env.example .env      # اختياري — بلا مفاتيح كل شي يخدم بالمحاكاة
npm install               # يثبّت غير SDK تاع Claude (اختياري)
npm start                 # http://localhost:3000/admin
npm test                  # يجرّب المسارات الستة
npm run seed              # يمسح القاعدة ويعاود بيانات التجربة
```

| الحساب | الإيميل | كلمة السر |
|---|---|---|
| مشرف | `admin@zinor.local` | `admin12345` |
| موظف | `agent@zinor.local` | `agent12345` |

> بدّل كلمات السر من صفحة «المستخدمين» قبل ما تحطّو على الإنترنت.

**باش تجرّب بلا مفاتيح:** افتح «محاكي واتساب» في اللوحة واهدر كأنك زبون (`salam ch7al livraison l Blida` …)، أو ابعث «طلب تجريبي من متجر» واضغط «نأكد الطلب». من بعد روح لـ«الشحن والروتور» وحاكي «خرجت مع الليفرور» وشوف التذكير يوصل.

## واش كاين

- **واتساب بالذكاء الاصطناعي** (`server/ai/`): يفهم الدارجة بالعربية وبالحروف اللاتينية والفرنسية، ويجاوب بنفس الطريقة. الأسعار والمخزون والتوصيل والتتبع يجيبهم من قاعدة البيانات عبر أدوات (tool use). يجاوب بصراحة إذا سقساوه واش هو روبو، ويحوّل للموظف كي يلزم.
  - مع `ANTHROPIC_API_KEY` ← **Claude** (`claude-opus-5-5`، قابل للتبديل بـ `AI_MODEL`، مع `fallbacks` تلقائي إذا النموذج رفض).
  - بلا مفتاح ← **محرّك محلي** بقواعد للدارجة يستعمل نفس الأدوات (للتجربة).
- **بلا مكالمة تأكيد:** الخادم هو اللي يقرّر — يبعث الملخّص الرسمي (المنتج + التوصيل + المجموع)، يسجّل الموافقة غير إذا جات **بعد** الملخّص الحالي، وكي تكمل المعلومات يسجّل الكوموند ويبعثها مباشرة لشركة التوصيل ويبعث للزبون التأكيد مع رقم التتبع. إذا تبدّل المنتج/الكمية/الولاية/طريقة التوصيل، الموافقة تتلغى ويلزم ملخّص جديد.
- **طلبات المتاجر:** ملخّص في واتساب بأزرار «نأكد الطلب / نبدّل المعلومات / نلغي الطلب». خارج نافذة 24 ساعة يتبعث **قالب معتمد**. التعديل يعاود يبعث الملخّص الجديد بالأزرار قبل الشحن.
- **الشحن الآمن:** تحقق من المنتج والثمن والمخزون والبيانات قبل الإرسال؛ مرجع فريد لكل طرد؛ إذا النتيجة غير واضحة (انقطاع بعد الإرسال) إعادة المحاولة **تتحقق عند الشركة أولاً** باش ما يتخلقش طرد ثاني. تحديث قديم ما يرجّعش الحالة للور.
- **التذكير قبل التوصيل:** مرة وحدة لكل محاولة توصيل حتى لو الشركة عاودت نفس الإشعار. الوقت المقدّر يتزاد غير إذا الشركة عطاتو. رسائل الشحن/التسليم/الفشل/الروتور تتفعّل من الإعدادات والنصوص قابلة للتعديل.
- **الروتور:** (1) طرد ما تسلّمش ورجع — يتحدّث من الشركة حتى «رجع للمخزن» والمخزون يرجع. (2) روتور بعد الاستلام عبر واتساب — السبب مربوط بالكوموند، سياسة قابلة للضبط (قبول تلقائي لأسباب معيّنة، الباقي لقرار الموظف)، وطلب جمع من الشركة إذا تدعمو.
- **لوحة تحكّم عربية RTL** (هاتف وكمبيوتر): الرئيسية بفلتر التاريخ، الطلبات (بحث بالهاتف/الرقم/التتبع + فلاتر)، صفحة الطلب (المنتجات، المبلغ، التوصيل، تاريخ الحالات، المحادثة)، صندوق واتساب (استلام المحادثة، الرد اليدوي، إرجاعها للمساعد، السجل يبيّن شكون ردّ)، الشحن والروتور، المنتجات، أسعار التوصيل للـ58 ولاية ومكاتب Stop desk، المتاجر، شركات التوصيل (افتراضية + قواعد حسب الولاية/الطريقة)، الإعدادات والقوالب، المستخدمين (مشرف/موظف)، سجلّ الإجراءات والأخطاء.
- **الأمان:** مفاتيح الربط مشفّرة (AES-256-GCM) على الخادم وما ترجعش للواجهة؛ تحقق من توقيعات webhooks (واتساب، Shopify، WooCommerce، Yalidine…)؛ منع تكرار الكوموند/الطرد/الرسالة/الحدث؛ كل زبون يشوف غير طلباتو (التتبع والروتور مربوطين برقمو).

## واش مربوط فعلياً وواش يحتاج مفاتيح

| الخدمة | الحالة في الكود | باش تخدم حقيقي |
|---|---|---|
| WhatsApp Cloud API | مبني على الواجهة الرسمية (رسائل، أزرار، قوالب، webhook موقّع، حالات الرسائل) | `WA_ACCESS_TOKEN`، `WA_PHONE_NUMBER_ID`، `WA_APP_SECRET`، `WA_VERIFY_TOKEN` + رابط عمومي HTTPS للـwebhook `PUBLIC_URL/webhooks/whatsapp` + **تسجيل القوالب** في Meta بنفس الأسماء (`zinor_order_confirm`، `zinor_out_for_delivery`…) وترتيب المتغيّرات |
| Claude | مجرّب على API وهمية محلية (حلقة الأدوات كاملة) | `ANTHROPIC_API_KEY` |
| Shopify | Webhook `orders/create` بالتوقيع الرسمي + مزامنة التتبع عبر GraphQL `fulfillmentCreate` | Admin API token بصلاحيات الطلبات/الـfulfillment + webhook secret |
| WooCommerce | Webhook «Order created» بالتوقيع الرسمي + تحديث الحالة والتتبع عبر REST v3 | Consumer key/secret + webhook secret |
| YouCan، Lightfunnels | استقبال الطلبات مبني على صيغة التوثيق؛ **رأس التوقيع ومزامنة التتبع يلزم يتأكدو** مع تطبيقك | حساب مطوّر/تطبيق عند المنصّة |
| Ayor، Justsell | **ما لقيناش توثيق API عمومي** ← Webhook JSON عام موقّع (صيغة Zinor أو خريطة حقول) | صيغة webhook والتوقيع وAPI التحديث من عند المنصّة |
| Yalidine | إنشاء الطرد، البحث بالمرجع، التاريخ، webhook — **مبني على توثيق Yalidine المعروف، لازم يتأكد مع نسخة التوثيق في حسابك** (ما قدرناش نوصلولها علنياً). جمع الروتور ما كانش في الـAPI العمومية | `API ID` + `API Token` (+ webhook secret) |
| ZR Express | واجهة Procolis القديمة (`add_colis`، `lire`، `token`) بالتحقق الدوري — **لازم تتأكد**. المنصّة الجديدة (Secret Key + Tenant ID) توثيقها ماشي عمومي | `Token` + `Key`، أو توثيق المنصّة الجديدة باش يتزاد موصّل `zr_express_v2` |

كل حساب ربط عندو وضع **«تجريبي»** (محاكاة كاملة تخدم بلا مفاتيح، معلّمة في اللوحة) و**«حقيقي»**. شوف `docs/CONNECTORS.md` باش تزيد شركة توصيل أو منصّة جديدة.

## البنية

```
server/
  index.js            الخادم (HTTP بلا مكتبات) + التحقق الدوري
  db.js               SQLite (node:sqlite) — الجداول كاملة
  ai/                 darija.js (الفهم) · tools.js (الأدوات + قرارات الخادم) · mock.js · claude.js · agent.js
  services/           orders · shipping · returns · stores · inbound (webhook واتساب) · whatsapp · notifications · accounts · settings
  connectors/
    carriers/         base.js (الواجهة الموحّدة + المحاكاة) · zr-express.js · yalidine.js · index.js (السجلّ)
    stores/           base.js · shopify · woocommerce · youcan · lightfunnels · ayor · justsell · generic.js
  routes/             api.js (اللوحة) · webhooks.js (واتساب، المتاجر، شركات التوصيل)
public/               لوحة التحكّم (عربي، RTL، بلا build)
test/flows.test.js    المسارات الستة + الأمان
index.html            واجهة المتجر الأصلية (تتعرض على /)
```

### روابط الـwebhook

- واتساب: `GET/POST {PUBLIC_URL}/webhooks/whatsapp`
- متجر: `POST {PUBLIC_URL}/webhooks/stores/{id}` (يبان في صفحة «المتاجر والربط» مع زر نسخ)
- شركة توصيل: `GET/POST {PUBLIC_URL}/webhooks/carriers/{id}` (للشركات اللي تدعم webhook)

### الإنتاج

- حط الخادم خلف HTTPS (Nginx/Caddy) وبدّل `PUBLIC_URL`.
- حط `APP_SECRET_KEY` (64 حرف hex) وخبّيه — هو اللي يشفّر مفاتيح الربط. بلاه يتولّد واحد في `data/.secret-key`.
- انسخ `data/` احتياطياً (قاعدة البيانات).
